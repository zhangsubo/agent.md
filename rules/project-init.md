# Project Initialization

## Trigger

当进入一个目录，且目录中没有项目级 `AGENTS.md`、`CLAUDE.md` 或其他明确的 Agent 入口文件时，先执行本流程，引导用户完成项目初始化。

如果用户只是临时询问、只读查看或明确不想初始化，不强制创建文件。

用户明确要求初始化或补全项目初始化时，即使已有 Agent 入口，也执行本流程中尚未完成的检查，保留已有配置。

## First Prompt

先给出结论：当前目录缺少项目级 Agent 入口，建议初始化。只询问阻塞当前初始化的缺失信息；先从现有目录和文档提取以下信息，非阻塞项使用合理默认值：

- 项目名称：默认使用当前目录名。
- 项目类型：优先从已有资料推断，无法判断时默认为软件开发；可选 `软件开发`、`产品设计`、`自媒体工作`。
- 项目简介：一句话说明项目要解决什么问题。
- 主要产出：例如代码仓库、PRD、原型、公众号文章、小红书图文、内容日历。
- 资料位置：是否已有 README、文档目录、需求材料、设计稿、素材库或 `Reference_myself/`。
- 保护范围：哪些文件、目录、数据或操作不允许自动修改。
- 验证方式：软件开发项目的启动、测试、构建命令；产品设计和自媒体项目的评审、交付或发布检查方式。

信息不足时使用合理默认值先生成草稿，并在文件中标记待补充项。

## Project Type Mapping

用户可见选项和规则模块映射如下：

| 用户选项 | 规则模块 |
|---|---|
| 软件开发 | `~/.agent-rules/rules/project-types/programming.md` |
| 产品设计 | `~/.agent-rules/rules/project-types/product-manager.md` |
| 自媒体工作 | `~/.agent-rules/rules/project-types/content-creator.md` |

如果用户使用近义词，例如“编程”“代码项目”“产品经理”“公众号”“小红书”，按最接近的项目类型映射。

## Files To Create

默认创建或建议创建：

- `AGENTS.md`：项目级 Agent 入口，包含项目类型、资料入口、操作边界、保护范围和验证方式。
- `CLAUDE.md`：如果用户使用 Claude Code，创建薄适配层，引用 `AGENTS.md`。
- `Reference_myself/00. README.md`：如果项目需要沉淀资料，创建文档清单和阅读路径。

若选择“产品设计”，优先使用 `~/.agent-rules/templates/project/product-design/AGENTS.md` 作为项目级 `AGENTS.md` 草稿。

不要把敏感信息、token、API key、密码或私有 endpoint 写入这些文件。

## AGENTS.md Minimum Structure

项目级 `AGENTS.md` 至少包含：

- `Project Type`：写明项目类型，使用 `软件开发`、`产品设计` 或 `自媒体工作`。
- `Project Knowledge`：说明项目资料入口和阅读顺序。
- `Protected Areas`：列出默认只读、禁止自动修改、需确认后修改的范围。
- `Verification Matrix`：写明检查、评审、测试、构建、发布前确认方式。

`Operational Overrides`、`Project Workflow`、`Documentation Writeback` 按项目需要添加，不要求固定章节。验证方式未知时标记待补充，至少执行入口和引用检查。

## Type Specific Defaults

### 软件开发

- 默认主要产出：代码改动、测试、技术文档、发布说明。
- 优先记录：技术栈、启动命令、测试命令、构建命令、部署边界、代码索引工具。
- 高风险操作：认证、支付、权限、数据删除、迁移、生产部署、依赖大版本升级。

### 产品设计

- 默认主要产出：需求澄清、PRD、用户故事、验收标准、流程图、原型说明。
- 优先记录：目标用户、业务目标、决策人、需求来源、评审方式、原型工具或设计稿位置。
- 产品规划与产物生成必须使用 `pm-workflow` skill。
- 高风险操作：范围变更、指标口径变化、影响排期或承诺用户交付的内容。

### 自媒体工作

- 默认主要产出：选题、标题、公众号文章、小红书图文、短视频脚本、内容日历。
- 优先记录：平台、账号定位、目标读者、语气、人设边界、素材库、发布检查清单。
- 高风险操作：事实数据、医疗法律金融等高风险建议、商业背书、未经授权素材、隐私信息。

## Orca Protection Enrollment

- 初始化项目时，检查当前项目是否已由 Orca 管理；不能仅凭安装了 Orca 就将所有目录视为 Orca 项目。
- 对 Orca 管理的项目，必须自动调用 `orca-worktree-private-data` skill，执行时读取并遵循其完整说明，完成已有私有资料备份、创建和归档 hooks 配置及接入验证。此项属于初始化范围，无需另行询问是否接入；不在本规则复制 skill 流程。
- 已接入的项目检查现有保护是否有效，仅补齐缺项，避免重复串联 hooks 或覆盖用户配置。配置保护不授权删除真实 worktree。
- 非 Orca 项目标记为不适用，不自动注册到 Orca。无法确认项目归属、Orca 不可用或 skill 缺失时，继续独立的初始化工作，明确列出保护接入阻塞，不得报告已保护。

## Initialization Output

完成初始化前，检查入口文件可读、实际引用路径存在、模板结构有效且未写入敏感信息；占位路径须明确标注待补充，不得声称已验证。修复可修复的问题后复查。

完成初始化后，简要说明：

- 已创建或更新哪些文件。
- 当前项目类型和对应规则模块。
- Orca 保护接入状态：已验证、不适用或受阻；适用时按 skill 的完成要求报告证据与限制。
- 用户后续可以补充的关键缺口。

如果用户不允许写文件，则输出可复制的初始化草稿，不创建文件。
