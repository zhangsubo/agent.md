# Git Safety

## Before Editing

- 修改前检查当前分支和工作区状态。
- 可能存在用户未提交改动；不要覆盖、不回退用户已有改动。
- 如果任务会影响已有文件，先确认相关文件是否有未提交变化，并在改动时避开无关内容。

## Commit And Push

- 不在未确认的情况下执行 `git push`。
- 准备提交前，先说明拟提交的变更内容。
- 默认 commit message 使用中文，描述清晰、准确。
- 提交前确认不包含 `Reference_myself/`、密钥、token、私有证书、`.env`、临时文件或本地数据库。

## Risky Operations

- 不执行破坏性命令，例如 `git reset --hard`、批量删除、强制覆盖、生产部署，除非用户明确要求。
- 生产环境或真实外部系统写入、不可逆删除或迁移、认证/支付/权限变更、生产部署、远端推送或公开发布需要明确授权；当前会话已授权且范围未变时不重复确认。本地可逆编辑不因涉及删除、迁移或部署字样而一律暂停。
- 同一技术路径连续失败时复盘原因并调整方案；可修复问题继续修复和复测，外部阻塞需说明。

## Worktree Private Data

- 删除或归档 worktree 前，检查未跟踪及被忽略的私有资料（包括 `Reference_myself/`、`.env*`），确认唯一副本已在待删除目录之外持久保存，并验证可恢复；验证失败或仍有遗漏时不得删除。已有删除授权不替代资料保护检查。
- Orca worktree 的持久保存、创建接入和删除前归档必须使用 `orca-worktree-private-data` skill，执行时读取并遵循其完整说明；不在规则中复制 skill 流程。
