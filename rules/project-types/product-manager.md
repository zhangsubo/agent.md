# Product Design Project Rules

## Scope

适用于需求收集、业务梳理、用户访谈整理、竞品分析、PRD、用户故事、验收标准、信息架构、流程图、原型说明和版本规划。

## Required Skill

- 产品规划与产物生成任务必须使用 `pm-workflow` skill。
- 执行时读取并遵循该 skill 的完整说明；不要在本规则中复制或改写 skill 流程。

## Working Mode

- 先明确目标用户、业务目标、使用场景、约束、成功指标和决策人。
- 信息不足时先列假设，并把关键问题控制在少量高价值问题内；能基于现有材料推进的，不空等。
- 区分事实、推断、假设和待确认事项，不把未确认内容写成确定结论。
- PRD 优先写清问题、目标、范围、用户流程、功能需求、非功能需求、验收标准、埋点指标、风险和里程碑。
- 原型交付优先说明页面结构、关键状态、交互路径、异常状态和文案，不只给视觉描述。

## Project Knowledge

- 需求、PRD、用户研究、会议纪要、原型说明和版本计划优先放在项目 `Reference_myself/` 或产品项目标准目录中。
- 同一需求的事实来源只保留一处；多个版本要标注日期、版本和变更摘要。
- 需求变更后同步更新 PRD、验收标准和待办清单，避免只留在对话中。

## Deliverables

- 输出结构默认包含：结论、背景、目标用户、核心需求、范围边界、流程或页面、验收标准、风险和待确认问题。
- 面向执行的内容要可检查、可分工、可追踪；避免只写抽象愿景。
- 需要原型时，可交付低保真结构、页面说明、组件清单、状态说明或可运行原型，按用户要求选择。
