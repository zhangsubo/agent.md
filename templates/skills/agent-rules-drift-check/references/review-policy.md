# Review Policy

## Context And Evidence

- 用语义审查对照实际 diff、项目规则与事实源；根据问题自行选择工具和检查顺序，不强制执行固定步骤。
- 只读取最小必要上下文；通过文档清单定位相关资料，上下文允许时读取更多相关资料。
- 结构性问题可用 GitNexus、CodeGraph、code-review-graph 或 language server；具体文本以实际 diff 和文件内容为准，不为形式调用全部工具。
- 图谱结论须与实际变更核对；索引不存在、过期或与 diff 不符时说明限制，不能把索引输出直接当作事实。是否重建遵循项目规则和已有授权。
- 大 diff 可按主题分批检查。每项发现提供变更证据、文档位置和判断理由，区分必须更新、建议更新、无需更新。
- 资料缺失时记录限制，不自动初始化事实源，不把缺证据写成确定结论。

## Review Dimensions

按变更相关性检查：

- 路径、目录角色、模块边界与构建、测试、启动、部署命令。
- API 路由、字段、鉴权、错误码与数据库表、字段、索引、迁移策略。
- 认证、权限、支付、数据删除等风险边界与 Agent 易误判的 gotcha。
- 项目 AGENTS.md 是否仅保留入口和必要边界；CLAUDE.md 是否保持薄入口。
- 项目事实是否已有单一来源；同编号旧版本是否应归档到 history_backup/。

## Read-Only Boundary

只生成审查建议，不自动修改源规则、代码或项目文档。报告是允许生成的交付物；建议的采纳和修改属于用户授权的后续任务。不要为产出内容强行提出建议，无漂移时输出 `No change needed`。
